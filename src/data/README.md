2026-11-08 정정: 가상 장소 625곳을 추가한 이전 구현은 사용자 의도와 달랐다. 운영 화면은 실제 장소만 사용한다. `places.json`, `events.json`의 예전 가상 데이터는 산식 단위 테스트용 `baseContent`에만 남아 있고 운영 모드로 선택할 수 없다.

## 표시 20곳 = 점수 반영 20곳 (최신 사용자 결정)

- NAVER API HUB 실제 후보 2,329곳에서 관광·활동 관련 1,930곳을 수록했다. 25개 동 모두 체인 의심 후보 제외 후 20곳을 초과하는 실제 후보가 있다. 좌표로 행정동 경계를 대조한다. 키는 수집 환경에서만 읽는다.
- 이전 구현의 “탐색 20곳, 점수는 검토된 일부만”은 요청을 충족하지 못했다. 2026-11-08 사용자가 표시한 20곳 전부 점수 반영을 재확인했으므로 기존 미확인 정보의 일괄 제외 정책을 대체한다.
- 점수 조건은 확인된 프랜차이즈/체인 의심 후보 제외, 확인된 휴무 제외, 관심 활동 일치다. 실제 검색 출처·좌표가 있는 장소의 운영/리뷰/분류 미확인은 **잠정 점수에 포함**하고 미확인 상태를 명시한다. 미확인을 영업 중·비프랜차이즈 확정·리뷰 0건으로 바꾸지 않는다.
- 출처 없는 가짜 장소는 허용하지 않는다. 분류 미확인인 개발용 가상 fixture에 이 완화를 적용하지 않는다. 알려진 프랜차이즈와 체인 의심 후보는 목록·점수·방문 기반 Lv에서 모두 제외한다. 모든 프랜차이즈를 찾아냈다고 보증하지 않는다.

- 실제 후보의 자기 신고 방문은 Lv에 반영한다. 추후 프랜차이즈/폐점 등을 확인하면 후보에서 제외하고 기존 기록은 보존한다.
- 2026-11-08 14:00 / 전체 활동 / 100 km에서 25개 동 모두 20/20이다. 관심 활동을 좁히면 해당 활동의 후보 수가 줄 수 있으며, 맞지 않는 업종으로 강제 보충하지 않는다. 후보 전체는 재선정용으로 보존하며, 사용자 요청에 따라 상세 상단의 ‘발견할 20곳·추천 장소·가본 장소·전체 후보’ 선택 영역은 제거했다.
- `discovery.excludedReason`은 브랜드/본점/지점 의심 필터다. 이름만으로 독립성을 확정하지 않는다. 수동 근거가 있는 판단은 `research/franchise-reviews.json`에서 관리한다.

## 리뷰·운영·분류 근거

`research/hamgae-observations.json`은 함께할개 공개 페이지에서 직접 찾은 사실값(이름·주소·좌표·숫자·시간표·출처)이다. 리뷰 본문·사진은 복제하지 않았다. 네이버 검색 결과와 이름·도로명 건물 번호·60m 이내 좌표가 모두 일치하는 300곳에만 리뷰 수를 연결했다. 이름만 같은 다른 매장에는 연결하지 않는다.

- `popularityEvidence`: 네이버 방문자 리뷰 수를 재인용한 **2차 출처**임을 표시한다. `count`를 실제 방문자 수라고 부르지 않는다. `observedAt`은 출처 갱신일, `source.checkedAt`은 이번 조회일이다. 출처 숫자는 실시간 자동 연동이 아니다.
- 알려지지 않은 숫자는 필드를 생략한다. 검색 순위·총 검색 건수·개인 방문 기록을 리뷰 수로 사용하지 않는다. 확인된 0과 결측은 별개다.
- `unknownDays`에 해당하는 요일은 미확인이다. 비어 있는 시간을 휴무/24시간 영업으로 만들지 않는다. 명시된 심야 영업은 자정 앞뒤 달력 날짜로 나누고, 요일별 휴게시간은 영업 구간에서 뺀다. 해석할 수 없는 구간·격주/월별 휴무는 보류한다. 입장·주문 마감과 임시휴무는 현장 안내 확인이 필요하다.
- `research/franchise-reviews.json`: 공개 운영자·매장 소개와 주소를 직접 대조한 수동 분류. 정부의 가맹 여부 인증이 아니며 재검토 가능하다. 운영정보만 있다고 비프랜차이즈로 자동 분류하지 않는다.
- `naver-places.json`: 성호박물관·최용신기념관·경기도미술관의 기존 공식 조사. 자료 기간 밖 운영 및 방문/리뷰 수 미확인은 잠정 점수로 표시한다. 확인된 휴무는 계속 제외한다.

## 외부 평균 별점 가점

`ratingEvidence`는 리뷰 개수와 별도로 평균 별점·5점 척도·제공자·2차 출처·확인일·원문 링크를 보존한다. 기존 함께할개 공개 HTML 356건 중 네이버 평균 별점이 명시된 121건을 추출했고, 이름·도로명 건물 번호·60m 이내 좌표 대조 후 앱 후보 1,199곳 중 75곳에 연결했다. 나머지 1,124곳은 미확인이다. 확인한 값의 범위는 1~5이며 출처 없는 값은 가점에 쓰지 않는다.

별점 가점 Q는 `min(평균 별점/5×30, max(0,100−B))`. B=70에서 4.28점인 레드지는 +25.68점으로 Lv.0 장소 점수가 95.68이다. 4.5점은 +27점, 5점은 +30점이다. Lv이 올라가도 이 가점과 외부 별점은 유지하고, 리뷰 **수**에 따른 감점을 따로 적용한다. 미확인은 평균 별점을 만들지 않고 가점만 0으로 둔다. 따라서 자료가 없는 장소끼리 동점인 현상은 남는다. 30점은 초기 조정값이며 별점 수집 범위 확대와 함께 보정 효과를 확인해야 한다.

현재 별점은 함께할개가 기재한 네이버 평균값의 2차 인용이며 실시간 NAVER 직접 조회값이 아니다. 카드에 평균 별점을 표시하고 접힌 출처에서 확인일·출처 갱신일·지도 원문을 볼 수 있다. 최신 디자인에서 제거한 내부 점수 설명은 복원하지 않는다. API 자동 수집에 별점이 추가됐다는 뜻이 아니다.

## 0~100점 정규화와 지도

장소 기본값 B=70은 동일한 정책값이며 조사된 별점/품질이 아니다. 출처가 있는 인지도 P는 같은 제공자·지표·기간의 비교 가능 후보에 대해 `log(1+count)/log(1+maxCount)`로 구한다. 확인된 수치는 실제로 쓰고, **미확인일 때는 count 필드를 만들지 않은 채 최대 인지도 감점 계수 1을 적용**한다. 이는 데이터 미확인이 낮은 인기보다 유리해지는 것을 막는 보수적 정책이며 측정값이 아니다. `w=(0,10,20,30)`이므로 Lv.0 인지도 감점 없음은 유지한다.

```
별점 가점 Q = 출처 있는 평균이면 min(별점/5×30, max(0,100−B)), 미확인이면 0
장소 점수 = max(0, B + Q − w[장소 Lv] × (확인된 P 또는 보수적 계수 1)) + 행사 가점
정규화 기본 점수 = 상위 20곳 점수 합계 / (20 × 110) × 100
유동인구 강도 I = 동 표시 상권 합계 / 전체 수집 자료의 최대 동별 합계 150,039
감점률 R = Lv별 상한(0 / 0.15 / 0.30) × I
최종 지역 점수 = 정규화 기본 점수 × (1 − R) × (새로움 배율 / 1.2) × 거리 배율
```

110은 장소 기본값과 별점 가점의 합 최대 100 + 행사 가점 최대 10의 고정 정책 상한이다. 새로움 배율은 1.2/1.1/1.0의 비율을 유지하되 최대값 1.2로 나눠 최종 100점 척도를 보장한다. 거리 배율은 `1/(1+km/20)`이다. 현재 결과의 최솟값·최댓값이나 관측 장소 수로 나누지 않는다. 다른 동이 필터에서 빠져도 같은 입력의 점수·색은 유지된다. 계산 중간은 반올림하지 않는다.

예: 장소 20곳이 각각 70점이면 기본 63.64점이다. 중앙동 Lv.1은 유동인구만으로 9.55점(15%)을 빼서 54.09점이 되며, 새로움·거리는 그 뒤 반영한다. 비교를 위한 같은 장소 합계의 예이며 실제 방문 후 장소별 감점까지 고정한 예가 아니다. Lv.2는 같은 기본점수에서 19.09점(30%)을 뺀다. 기존 1,400점에서 3.21점을 빼던 방식은 폐기했다.

내부 지역 점수는 0~100점이며 추천 순서에 사용한다. 최신 팀 디자인의 메인 지도는 친밀도 색상을 사용하고 점수 숫자·점수 모드 전환을 노출하지 않는다. 내 동네 빗금·도심/대부도 슬라이드와 S 마커 제거를 유지한다. 이번 별점 수정에서 지도 색상 정책을 되돌리지 않는다.

### 사동 추억 표시 예시 (2026-11-08 사용자 요청)

사동(`dong-4127152500`)에서만 기존 실제 후보 중 무작위 2곳을 ‘추억 예시’ 카드와 하트 마커로 표시한다. 별도의 장소 데이터·가짜 방문일·리뷰 수를 만들지 않는다. 예시 선택은 `ansan-explore/sadong-memory-preview/v1`에만 저장하며 방문 기록, 초기 Lv, 점수, 상위20 선정에는 반영하지 않는다. ‘다른 예시 보기’/‘예시 숨기기’로 비교할 수 있다. 사용자가 해당 장소에 직접 방문 기록을 남기면 실제 추억 한 건으로 표시하며 예시와 중복하지 않는다. 나머지 24개 동은 실제 방문 기록만 표시한다.

### 브라우저용 최소 데이터

- `research/real-places.json`은 출처 대조·재분류용 원본 1,930곳이다. 브라우저에서 import하지 않는다.
- `places.runtime.json`에는 제외 정책을 통과한 실제 후보 1,199곳만 넣는다. 체인 의심으로 이미 제외된 731곳과 수집용 원분류 문자열은 내려보내지 않는다. 상위 20곳 밖의 **예비 후보도 모두 유지**하며 기존 ID와 저장된 방문 기록은 바꾸지 않는다.
- 장소명·동·앱 분류·주소·좌표·운영정보·방문자 리뷰 수·외부 평균 별점·출처는 보존한다. 반복되는 기본값/출처는 한 번 저장하고 로딩 시 복원한다. 네이버 검색 링크는 같은 동명과 장소명으로 원래 URL을 복원한다. 다른 출처/기본값을 가진 개별 장소의 예외는 그대로 저장한다.
- `npm run content:prepare`가 원본에서 배포용 파일을 생성한다. 수집 결과 가져오기와 `npm run dev` / `npm run build`도 이 단계를 실행한다. 배포용 JSON은 직접 수정하지 않는다.
- 리뷰 감점 기준 최댓값은 추천 계산 한 번당 전체 후보를 한 번만 읽어 산출한다. 자료가 변경되면 다음 계산에서 다시 생성하므로 리뷰/분류 갱신과 방문 후 재선정을 가로막는 영구 캐시는 없다.
- `placePayload.test.ts`는 전체 후보의 기능 필드·정확한 출처 URL 보존, Lv.0/1/2·방문·관심 활동별 점수/선정 결과 동일성을 원본과 비교한다.

```sh
node --experimental-strip-types --env-file=.env.local scripts/collect-ansan-candidates.mjs --out .local/ansan-real-candidates --target 25 --max-requests 1800 --evidence src/data/research/hamgae-observations.json
node scripts/extract-hamgae-ratings.mjs .local/place-evidence-20261108 src/data/research/hamgae-observations.json
node scripts/import-real-places.mjs .local/ansan-real-candidates/candidates.json src/data/research/hamgae-observations.json
npm test
node --test scripts/naver-candidates.test.mjs scripts/lib/real-place-import.test.mjs
npm run build
```

별점 추출 단계에는 이미 저장한 공개 HTML 캐시가 필요하다. 누락 파일이면 실패하며 네트워크 수집을 수행하지 않는다. 기본 빌드에는 커밋된 숫자 관측자료만 사용하고 HTML은 포함하지 않는다.

수집기는 중간 저장·동일 질의 재사용·호출 상한·좌표 배정·출처 보관을 한다. 인증/네트워크 오류는 빈 성공으로 숨기지 않는다. 가져오기는 어느 동이든 체인 의심 제외 후 20개 미만이면 실패하여 부족한 데이터를 배포하지 않는다. 후보의 분류 검토와 수치 확인은 별개 단계다.

다음 자동화는 (1) 공식 검색 API로 변경 후보만 갱신, (2) 이용 허용된 데이터 제공자/업체 제공 자료로 리뷰·시간 수집, (3) 이름·주소·좌표 대조, (4) 급격한 리뷰 감소·폐점·분류 충돌 검토 대기, (5) 검증 후 스냅샷 반영 순서가 적합하다. 현재 지역검색 API는 리뷰 숫자·평균 별점·영업시간을 주지 않는다. 차단 응답을 우회하거나 키를 브라우저에 노출하는 수집은 추가하지 않았다. 자동 일정은 생성하지 않았다.
