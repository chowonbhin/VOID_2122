2026-11-08 사용자 요청: 2개 탐험권역을 **안산 25개 행정동**으로 교체했다. 실제 장소는 출처·운영·프랜차이즈 확인 후 순차 반영한다. 이후 사용자 요청으로 아래의 임시 시연 보완 모드를 기본 활성화했다.

## 임시 시연 보완 모드 (2026-11-08 최신 요청)

- `demoPlaces.ts`가 동마다 **25개, 총 625개 가상 후보**를 추가한다. 전체 활동에서는 현재 점수 상위 20개를 합산하고 나머지를 재선정 후보로 유지한다. 기존 원본 15곳과 실제 장소의 미확인 정보는 바꾸지 않는다.
- 이름은 `시연 <동명> <활동> <번호>`, ID는 `demo-<행정기관 코드>-<번호>`로 고정한다. 실제 동 경계 안에 재현 가능한 가상 좌표를 생성하며 실제 업체·운영·방문·리뷰 수라고 표시하지 않는다. B와 P는 시연값이고 운영은 시연에서만 매일 00:00~24:00으로 설정한다.
- 첫 실행 온보딩 완료 시 전체 활동·최대 직선거리 100 km·현재 한국 시각을 적용해 대부동까지 25개 동 모두 **20/20개**를 제공한다. 기존 검색 조건과 방문 기록은 유지한다. 화면의 **25개 동 시연 조건 적용** 버튼으로 전체 활동·100 km 조건을 적용할 수 있으며 날짜·익숙함·방문 기록은 보존한다.
- 관심 활동·거리 조건은 계속 유효하다. 좁혀 검색하면 20개 미만이나 제외된 동이 생길 수 있으며 N/20과 부족 이유를 그대로 표시한다. 점수를 강제로 고정하거나 지역 점수 수식을 바꾸지 않는다.
- 화면의 **추가 시연 장소 끄기/켜기**로 원본 데이터와 전환한다(`ansan-explore/demo-fill`). 전환은 추가 후보만 바꾸고 방문 기록을 삭제하지 않는다. 실제 장소의 운영·인지도 미확인, 프랜차이즈·분류 미확인 제외 정책도 유지한다.
- 상세 화면 기본은 추천 20곳, 전체 장소에서 모든 후보를 확인한다. 지도 마커는 8곳씩 페이지로 표시하고 카드 선택 시 해당 지도 페이지로 이동한다. 기존 손그림 경계·집·추억 디자인은 유지한다.
- 검증: 25개 동 모두 야간/주간 상위 20개, 각 동의 20번째 후보 방문 시 예비 후보 편입, 다른 동 불변, 삭제 복원, 실제 자료 미확인 제외. 브라우저 검증도 기본 활성 모드와 원본 모드를 각각 실행한다.
- 이 보완은 기능 시연용이다. 실제 후보 413개의 운영·프랜차이즈·리뷰 조사나 실제 추천 품질 검증을 완료한 것은 아니다.

## 행정동과 기록

- 상록구 13개 + 단원구 12개. `dong-<10자리 행정기관 코드>`가 Region ID다. 법정동·상권을 추천 단위로 혼용하지 않는다.
- 경계 버전 2026-10-01, 출처·라이선스·재생성은 [geography/README.md](geography/README.md).
- 지도는 행정동 경계에 동일한 0~3,000+ 점수 색상 척도를 적용한다. 상위 20개 합산에 맞춘 표시 범위이며 원점수는 바꾸지 않는다. 0점은 연녹색, 자료 없음/조건 미충족은 회색이다. 최신 디자인의 도심/대부도 슬라이드·미니맵을 유지하고 작은 동은 동 목록으로 선택한다. 추천 지도는 외부 타일을 요청하지 않는다. 상세 지도도 최신 팀 디자인의 손그림 SVG 경계·추억 마커를 사용한다. 내 동네 집 표시·추억 예시를 유지하며, 예시 추억은 방문 기록·점수에 반영하지 않는다. 예시의 동 소속은 현재 경계와 좌표로 연결한다.
- 각 장소는 한 행정동에만 속한다. 기존 좌표를 경계와 대조했다. a1~a5와 a6-franchise는 중앙동, b1/b2/b4/b5와 b6-unverified는 원곡동, **b3는 신길동**이다. 기존 장소 ID와 방문 기록은 유지한다.
- `region-a/b` 초기 익숙함은 여러 동에 자동 복사하지 않는다. `legacyInitialLevels`에 보관하고 `needsDongLevelReview`로 다시 선택하도록 안내한다. 직접 신고한 행정동 Lv은 유지한다. 구형 상세 링크는 중앙동/원곡동으로 연결한다.
- 중앙동/원곡동은 기존 역 시작점과 출처를 유지한다. 다른 동은 경계 내부 대표 지점으로 거리를 계산하며 시설 입구가 아님을 표시한다. 상세 지도 번호는 Place.location에 연결한다. 좌표 미확인 장소는 임의의 핀을 만들지 않는다.

## 네이버 후보·개별 수치·상위 20개

API HUB 실요청으로 25개 동에서 후보 413개를 확보했다. 기존 검증 시설 3곳의 좌표·검색 출처를 `naver-places.json`에 연결했다. 방문·리뷰 수는 여전히 미확인이고 나머지 후보는 검토 대기다. 집계는 `naver-collection.json`, 원본은 Git 제외 `.local/naver-api-hub-20261108/`에 보관한다. [키 발급·수집·검토 안내](../../docs/naver-place-data.md).

- API는 검색어당 최대 5건이다. 여러 검색어 결과를 모아 좌표로 동 경계를 확인하고 중복을 제거한다. 네이버지도 화면 순위와 동일하다고 표현하지 않는다.
- 실제 P는 **개별 장소의** `popularityEvidence.count`를 같은 제공자·지표·기간의 최대 수치로 로그 정규화한 값이다. 방문자 리뷰 수·블로그 리뷰 수·실제 방문수를 섞지 않는다. 앱의 개인 방문 기록은 Lv에만 사용한다.
- 확인된 0은 유효하지만 결측은 점수에서 제외한다. 상세에는 출처와 확인일 또는 수치 확인 필요를 표시한다. 기본 가치는 현재 시연 기준이다.
- 모든 후보를 보관하고 방문·기록 삭제·조건 변경 시 전체를 재평가한다. 현재 장소 점수 내림차순, 동점 ID 순의 20개를 합산한다. 방문 장소가 여전히 상위 20개면 유지한다.

## 프랜차이즈 제외

`placeEligibility.ts`의 출처가 있는 비프랜차이즈만 허용하는 정책을 점수·목록·지도·행사·방문 Lv에 공통 적용한다. 가맹점과 동일 브랜드 직영 체인 모두 제외한다. 이름만으로 추정하지 않으며 필드·근거가 빠지면 unknown으로 제외한다. 직접 탐색도 동일하다.

`a6-franchise`(영업 중 B100/행사+10)와 `b6-unverified`(영업 중 B100)는 제외 검증용 가상 데이터다. 이들의 방문 기록은 보관하지만 점수에 영향을 주지 않는다. 원자료 유동인구를 ‘프랜차이즈를 제외한 인구’로 재해석하지 않는다.
